# Zvuk — Telegram media bot

Асинхронный Telegram-бот на Python 3.11+, aiogram 3, yt-dlp, FFmpeg, PostgreSQL (без Redis). Поддерживает поиск музыки по названию и исполнителю, публичные ссылки YouTube, VK, Rutube, TikTok, Instagram, Pinterest, Яндекс.Музыки, а также ссылки на отдельные треки Spotify и Deezer через поиск по метаданным.

## Возможности

- Поиск песни по названию через yt-dlp/YouTube: до 10 результатов, 5 на странице; нажимать на разные треки можно независимо, повторная отправка уже полученного формата запрещена.
- Ускоренные и замедленные аудиоверсии (1.25× и 0.80×): FFmpeg atempo, отдельный файл и ключ кэша.
- Кнопки MP3, MP4, 1.25×, 0.80× для видеоплощадок и три аудиоформата для музыкальных ссылок.
- PostgreSQL-кэш Telegram `file_id` по нормализованной ссылке и типу файла.
- До 5 разных файлов в очереди на пользователя, один воркер может последовательно обрабатывать их с ограниченным расходом CPU.
- Отдельный воркер: скачивание не блокирует получение обновлений Telegram.
- Атомарная защита от повторных отправок и одновременных задач через PostgreSQL advisory-lock; PostgreSQL хранит временную сессию и долговечную очередь.
- PostgreSQL LISTEN/NOTIFY с долговечными заданиями, SQL-арендами и восстановлением после сбоя.
- Обязательная подписка на спонсорские каналы; бот должен быть их администратором.
- Рекламный текст в caption, который администратор меняет без перезапуска.
- Встроенная /admin: статистика с размером очередей, каналы, подпись, подтверждаемая рассылка с прогресс-баром и остановкой, кнопка проверки состояния сервисов.
- Команда /health в личном чате доступна администраторам и проверяет Telegram Bot API, PostgreSQL, временные состояния и heartbeat воркера.
- Rate limiting новых поисковых/ссылочных сообщений; кнопки разных треков не блокируются лишним троттлингом (их защищают ограничения PostgreSQL).
- Временные директории удаляются после отправки, включая исключения; старые каталоги после аварий очищаются при запуске воркера (через 24 ч).
- Local Bot API в режиме `--local`: отправка файлов до **2000 МБ** (не 2 GiB).
- Proxy rotation между заданиями; cookies.txt опционально только для администраторов.

## Быстрый запуск

1. Скопируйте `.env.example` в `.env`. Настройте `BOT_TOKEN`, `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `ADMIN_IDS` и обязательно задайте одинаковый пароль в `POSTGRES_PASSWORD` и `DATABASE_URL`.
2. `TELEGRAM_API_ID`/`TELEGRAM_API_HASH` — ключи приложения с [my.telegram.org](https://my.telegram.org); это **не** токен бота. Если токен ранее работал с публичным Bot API, перед переносом на Local Bot API нужно выполнить официальный метод `logOut` публичного API и затем запускать локальный сервер.
3. Для Spotify: зарегистрируйте приложение в [Spotify Developer Dashboard](https://developer.spotify.com/dashboard) и задайте `SPOTIFY_CLIENT_ID`/`SPOTIFY_CLIENT_SECRET`. Без них ссылки Spotify возвращают явную ошибку настройки, остальные сервисы доступны.
4. Запустите `docker compose up --build -d`. Миграции выполняются сервисом `migrate` до старта бота и воркера.
5. Просмотр логов: `docker compose logs -f bot worker`. Напишите боту `/start`, отправьте ссылку или просто название песни и выберите результат. В личном чате отправьте `/admin` или `/health` с ID из `ADMIN_IDS`.

Контейнер `media-init` выставляет права на общий том для непривилегированного воркера. Временные файлы доступны локальному Bot API на чтение до завершения отправки.

Локальный Bot API не опубликован на хосте и доступен только внутри Docker. Том `media_tmp` общедоступен воркеру и локальному Bot API по пути `/shared`, что необходимо для локальной отправки файлов.

## Как работает скачивание

1. Handler принимает ссылку (строгий allowlist доменов), предлагает MP3/MP4 и выбор темпа (в музыкальных сервисах — только аудио).
2. Middleware проверяет обязательную подписку, затем PostgreSQL атомарно проверяет прежние успехи, активные задачи и лимит пользователя (до любого обращения к медиакэшу).
3. При новой задаче создается запись `download_history`; если есть глобальный кэш Telegram `file_id`, файл отправляется без скачивания, иначе воркер просыпается от транзакционного PostgreSQL NOTIFY.
4. Worker берет задачу, ставит распределенную блокировку по cache key, скачивает через `asyncio.to_thread(yt-dlp)`, конвертирует FFmpeg при необходимости и отправляет файл.
5. Worker сохраняет Telegram `file_id` и освобождает блокировку; временные файлы исчезают по выходу из `TemporaryDirectory`. Другие запросы того же медиа получают `file_id` из кэша.

Рекламная подпись подставляется при **каждой** отправке, в том числе при попадании в кэш.

## ОП и админка

В `/admin` выберите «Спонсорские каналы»: можно добавить публичный канал по `@username`, либо приватный по строке `-100xxxxxxxxxx | https://t.me/+invite`. Бот обязан быть администратором канала для корректной проверки участников. В «Рекламная подпись» установите до 1024 символов или `-` для отключения. В «Рассылка» отправьте текст или медиа и подтвердите запуск отдельной кнопкой. После старта есть кнопка «Остановить рассылку». Бот копирует сообщение пользователям, сохраняет курсор после каждого получателя и обновляет визуальный прогресс каждые 25 получателей. Отмена не удаляет уже доставленные сообщения. `/cancel` отменяет ввод админского действия.

## Эксплуатационные ограничения

- Поиск по тексту выполняется по открытым метаданным YouTube. Это не поиск по словам из текста песни и не музыкальное распознавание (Shazam).
- Возможность скачивания зависит от сайта, авторизации, доступности контента и изменений его защиты. Прокси не гарантируют доступность.
- Spotify и Deezer используются **только для метаданных**. Затем `ytsearch1:` пытается найти похожую независимую запись на YouTube; результат может отличаться от исходного трека. Spotify DRM/потоки не извлекаются.
- Файлы сверх 2000 МБ не отправляются. Установлен запас 1990 МБ. Для крупных файлов требуется запас временного диска и времени на транскодирование.
- PostgreSQL-очередь обеспечивает доставку *at-least-once*. При падении сразу после отправки, но до записи статуса, возможна повторная отправка. Для строгой семантики exactly-once нужна дополнительная бизнес-процедура.
- PostgreSQL отслеживает аренду выполняемых задач, восстанавливает просроченные записи через 10-минутную аварийную проверку; семантика at-least-once.
- Временные ошибки БД и Telegram повторяются до 3 раз; после исчерпания попыток задача завершится с ошибкой. Автоматическое восстановление после падения процесса может повторно доставить последний файл.
- Ограничение MAX_PENDING_PER_USER реализовано транзакцией PostgreSQL с `pg_advisory_xact_lock(user_id)`: несколько параллельных нажатий того же пользователя сериализуются и не обходят лимит.
- Cookies администратора не применяются к обычным пользователям; их кэш изолирован ID пользователя. По умолчанию запросы работают без cookies.
- Проверять E2E нужно на реальном Bot API и тестовых URL: CI выполняет unit-тесты и Docker Compose config, но не проверяет доступность сторонних площадок. См. [операционный чек-лист](docs/OPERATIONS.md).
- Используйте бот только с материалами, на которые у вас есть права, соблюдая правила площадок и применимое законодательство.

## Музыкальная библиотека, распознавание и монетизация

- `/save <url> | Необязательное название`: сохранить ссылку в персональную библиотеку PostgreSQL, `/library`: последние 20 записей с кнопками воспроизведения и удаления. Можно сохранять треки кнопкой 💾 в результатах поиска.
- Голосовые, аудио, видео и кружки: бот извлекает короткий звуковой фрагмент FFmpeg и отправляет его в AudD для определения названия/исполнителя. Затем ищет открытые совпадения через YouTube. Понадобится `AUDD_API_TOKEN` (внешний сервис, пользователь предупрежден). Плата за AudD может расти с количеством распознаваний.
- `/premium`: разовое начисление Premium на 30 дней за Telegram Stars (`XTR`). Счет создается только в личном чате, `pre_checkout_query` сверяет пользователя, сумму и payload; доступ открывается строго после `successful_payment`, повторные события обрабатываются идемпотентно.
- Premium убирает рекламные подписи, но не отключает обязательные подписки. Плата взимается за функции бота, не за контент и не за право прослушивания чужих произведений.
- Администратор может создавать рекламные размещения: `/campaign_add Название | Текст | https://example.org | 1000`; `/campaigns` — статистика, `/campaign_on ID`, `/campaign_off ID` — включение и отключение.
- Кампании показываются вместо старой рекламной подписи. Счетчик показов увеличивается после успешного ответа Telegram, не после запросов. Статистика — **best effort**: при падении между успешной отправкой и фиксацией в БД возможен недоучет; одновременные отправки могут немного превысить заданный лимит до фиксации счетчиков.
- Включенный `AdPost` — запасная рекламная подпись, когда активных кампаний нет. Для нее отдельный счетчик не ведется.
- `PREMIUM_PRICE_STARS`, `PREMIUM_DAYS`, `AUDD_API_TOKEN`, `RECOGNITION_MAX_INPUT_MB`, `FREE_RECOGNITIONS_DAILY`, `PREMIUM_RECOGNITIONS_DAILY`, `SUPPORT_USERNAME` настраиваются в `.env`.

### Учет доходов

Отчет `/campaigns` показывает число подтвержденных рекламных отправок. Заданные лимиты — не гарантия охвата. Оплата рекламодателей, договоры, налоговый учет и возвраты Stars выполняются отдельно; это не автоматический биллинг рекламодателей. Перед публичным запуском проверьте оплату Stars и отмену платежей на реальном боте. Следите за стоимостью AudD, CPU и исходящим трафиком: количество пользователей само по себе не означает прибыль.

### Безопасный запуск монетизации

В `.env.example` платежи по умолчанию **выключены** (`PREMIUM_ENABLED=false`). Для включения владелец должен установить `SUPPORT_USERNAME` (ник поддержки без @), `PREMIUM_PRICE_STARS`, проверить прием `successful_payment` на работающем Local Bot API и только затем выставить `PREMIUM_ENABLED=true`. Старые неоплаченные счета истекают для подтверждения через 30 минут. Покупка разовая, без автопродления. Платежные события сохраняются с `telegram_payment_charge_id` для проверки и возможного возврата средств, но команда автоматического возврата еще не реализована.

В `/admin` также отображаются количество активных Premium, оплаченных заказов и полученные Stars. Это валовые Stars, **не чистая прибыль и не рублевый баланс**.

AudD имеет платные тарифы, даже если доступна бесплатная пробная квота. `RECOGNITION_MONTHLY_CAP=300` задает верхний предел распознаваний через PostgreSQL на календарный месяц (UTC); `FREE_RECOGNITIONS_DAILY=3`, `PREMIUM_RECOGNITIONS_DAILY=20` — индивидуальные дневные лимиты. Счетчики сохраняются в PostgreSQL; при ручном удалении данных или сбоях биллинга возможны расхождения: для строгого финансового лимита понадобятся серверные квоты в AudD/биллинге. Стандартный endpoint AudD анализирует первые ~12 секунд клипа. Запуск с `AUDD_API_TOKEN` допускается только после настройки внешнего аккаунта и согласования стоимости.

`/privacy` и `/terms` дают пользователям информацию о собираемых данных и условиях. Записи БД пока не удаляются автоматически: запросы на удаление принимаются через контакт поддержки. Обязательно адаптируйте тексты документов под ваше юридическое лицо, регион и действующие правила перед коммерческим запуском.

На Windows 10/11 с Docker Desktop и системным VPN первым делом сравните
внешние IP Windows и Docker-контейнера. [Пошаговый запуск и VPN-диагностика](docs/LOCAL_TESTING_WINDOWS.md)
содержит команды PowerShell, напоминание о `logOut` для Local Bot API,
настройки `.env` и smoke test.

Когда Compose уже запущен, выполните безопасную сетевую самопроверку:

```powershell
docker compose run --rm --no-deps bot python -m app.tools.preflight
```

`PROXIES` применяется только к скачиванию через yt-dlp, а не ко всем
сервисам Telegram/Spotify/AudD. Полный VPN-маршрут нужно подтвердить
сравнением публичного IP, иначе отдельные контейнеры могут обходить VPN.

## Плейлисты и домашнее меню

- `/start` и `/menu` — кнопочное главное меню (поиск, распознавание, избранное,
  плейлисты, Premium, помощь).
- `/playlist new Название` — создать (до 25 на пользователя).
- `/playlists` — открыть плейлисты; `/playlist show ID` — открыть треки.
- `/playlist add ID https://ссылка | Название` — добавить трек по ссылке
  (до 200 в одном плейлисте; дубликаты не добавляются).
- `/playlist delete ID` — удалить весь плейлист. Есть кнопки проигрывания и

- `/fragment текст песни` — приблизительный поиск через YouTube с добавлением
  слова `lyrics`. Это **не** точный поиск по базе полных текстов и не гарантия
  определения песни по словам. Сам текст песни бот не воспроизводит.

## Учет окупаемости

Администратор может использовать `/income 1500 | Реклама | Название заказчика`,
`/expense 1100 | Хостинг | VPS`, `/economics` либо кнопку «Доходы и расходы»
в `/admin`. Учитываются только **фактически внесенные вручную операции в
целых рублях**, без валютных пересчетов. Поступления Telegram Stars отображаются
отдельно; рекламные показы не считаются оплатой. Разница доходов и расходов до
налогов **не** равна итоговой чистой прибыли.


## Легкий поиск, без дублирования файлов

Отправьте имя исполнителя (например, `lil peep`) — бот покажет до 10
результатов по 5 на странице. Весь список доступен 30 минут, а каждая кнопка
работает независимо: пользователь может выбрать одну, три или пять разных песен
без «скачать следующие N».

- `🎧 01` — получить только выбранный файл.
- `⭐ В избранное` — сохранить ссылку в личной библиотеке.
- `➕ Плейлист` — выбрать целевой плейлист и сохранить туда трек.
- `✅` — этот формат файла уже отправлялся этому пользователю; повторное
  скачивание и отправка блокируются до запроса к медиакэшу и yt-dlp.
- `⏳` — файл уже поставлен в очередь или обрабатывается; второе задание
  не создается. После неудачной загрузки запись становится `failed` и
  пользователь может повторить запрос.

История успешных отправок хранится в PostgreSQL и учитывается даже после
перезапуска Docker и при новом поиске той же записи. MP3 и MP4 считаются
разными форматами: один пользователь может получить каждый формат однократно.
Другая учетная запись Telegram может получить ту же запись из общего
Telegram `file_id`-кэша (без скачивания с сайта).

Нажатие кнопки требует одного запроса PostgreSQL для поисковой сессии.
Отдельные ключи выбранных треков, блокировки поиска и массовая отправка не нужны.
Состояния 5–10 треков читаются одним запросом PostgreSQL.

Новая задача резервируется в транзакции PostgreSQL. Лимит по умолчанию —
5 незавершенных файлов на одного пользователя; при
`WORKER_CONCURRENCY=1` они обрабатываются последовательно, без пяти
одновременных FFmpeg-процессов.

Для живого теста на существующей Windows-машине укажите в своем `.env`:
`MAX_PENDING_PER_USER=5`, сохраните изменения, затем выполните
`git pull --ff-only` и `docker compose up --build -d`. Тома Docker
не удаляются.

### Нестабильность YouTube

Для временных сетевых ошибок и HTTP 5xx загрузчик выполняет одну дополнительную попытку
с небольшой паузой. При HTTP 429, проверке `Sign in to confirm you're not a bot`,
приватности видео или явной необходимости авторизации автоматических повторов нет,
чтобы не усиливать ограничения площадки. Сообщения об ошибках разделены по типам:
антибот-ограничения больше не выдаются за доказанную приватность видео.

Ни одна автоматическая обработка ошибок не гарантирует скачивание конкретного ролика.
Если один URL то работает, то не работает, проверьте `docker compose logs --tail=100 worker`,
сетевое подключение, актуальность yt-dlp и условия площадки. Не публикуйте токены/cookies
в логах и сообщениях.


## Короткие видео: Reels, Shorts, TikTok (автоматически MP4 + MP3)

Когда пользователь присылает **ссылку на Instagram Reels, YouTube Shorts
или отдельное TikTok-видео**, Zvuk сразу принимает **одну** задачу
без выбора формата. В ответ бот:

1. скачивает доступное видео и отправляет его как воспроизводимый MP4;
2. извлекает звуковую дорожку **из этого же видео** с помощью FFmpeg
   и присылает MP3 отдельным сообщением.

Второго скачивания с Instagram/YouTube/TikTok для аудио не требуется.
При отсутствии звуковой дорожки бот отправит видео и объяснит,
почему MP3 отсутствует. Это извлеченный оригинальный звук ролика,
**не** распознанная полная студийная версия песни: для идентификации
самостоятельного трека потребуется отдельный сервис распознавания.

Поддерживаются ссылки вида `instagram.com/reel/<id>/`,
`youtube.com/shorts/<id>`, `tiktok.com/@author/video/<id>`
и `vm.tiktok.com` / `vt.tiktok.com` (если ссылка разрешается площадкой).
Параметры отправки из Instagram/TikTok удаляются при каноникализации
для общего ключа кэша. Обычные YouTube `watch?v=...` по-прежнему
показывают выбор MP3/MP4/скорости.

Оба Telegram `file_id` сохраняются **раздельно** в общем кэше. Для новых
пользователей доступны повторные отправки без обращения к медиаплощадке.
Уже доставленные видео и MP3 фиксируются отдельно в истории пользователя:
если загрузка аудио сорвется после отправки видео, следующая попытка
не отправит видео повторно. Видео может быть взято из Telegram-кэша
для извлечения недостающей звуковой дорожки. Платная рекламная подпись
показывается только под видео, чтобы не дублировать рекламу под MP3.

Лимиты `MAX_FILE_MB`, `MAX_DURATION_SEC`,
`MAX_PENDING_PER_USER` и `WORKER_CONCURRENCY` продолжают действовать.
Закрытые записи и сайты, требующие авторизации, могут оставаться
недоступными. Нет обещаний снять ограничения Instagram/TikTok или
загрузить любой ролик. Используйте только контент, который разрешено
скачивать и обрабатывать.


## Развертывание без Redis и Upstash (PostgreSQL-only)

В этой версии PostgreSQL является единственной системой для данных и
очереди: пользователей, плейлистов, рекламы, премиальных платежей,
временных поисковых кнопок и состояния администраторской панели.

При отправке ссылки бот в одной транзакции резервирует задачу и вызывает
`pg_notify('zvuk_jobs', 'download')`. Воркер слушает
`LISTEN zvuk_jobs`, извлекает задачи через `FOR UPDATE SKIP LOCKED`
и обрабатывает их. **В период без запросов нет трехсекундного опроса.**
Когда воркер перезапускается, он начинает с проверки сохраненных
заданий. Раз в 10 минут выполняется редкая аварийная проверка на случай
пропущенного уведомления или истечения аренды после сбоя.

Доставка подтверждается через `delivery_receipts`:
`user_id + cache_key`. Запись остается даже после удаления подробных
логов скачивания старше 30 дней, поэтому пользователь не сможет
повторно скачать уже полученный формат. Кэш Telegram `file_id` остается
в таблице `media_cache`; большие MP4/MP3 никогда не записываются в
PostgreSQL. Через 24 часа чистятся просроченные временные состояния.

`REDIS_URL`, отдельный Redis-контейнер и Upstash больше не нужны.
Обновление через Alembic `0007` переносит существующие успешные
выдачи в таблицу подтверждений, чтобы дедупликация сохранилась.
Старые краткоживущие Redis-кнопки не мигрируются; после перехода
нужно просто повторить поиск.

### Ограничения этой архитектуры

`LISTEN/NOTIFY` требует постоянного прямого соединения с PostgreSQL.
Транзакционный PgBouncer не подходит для таких уведомлений.
Нужен запущенный worker, способный обрабатывать задачи, и Telegram
Bot API. После сбоя связи между Telegram и записью подтверждения
теоретически возможно повторное сообщение: добиться строгой гарантии
exactly-once в стороннем Telegram API невозможно.

После обновления с локального Docker при необходимости используйте
`docker compose up --build -d --remove-orphans`, а не `down -v`.
Проверяйте миграции и /health прежде чем приглашать пользователей.


### Скачивание одинакового медиа разными пользователями

Синхронизация одинаковых файлов использует session-level advisory locks
PostgreSQL. При конкурирующих запросах один worker получает блокировку
по хешу ключа медиа; другие ожидают в PostgreSQL без опроса каждые 3
секунды, а затем проверяют общий `media_cache`. Если процесс погибнет,
блокировка автоматически освобождается вместе с SQL-соединением.
Ограничение на общее количество одновременных обработок по-прежнему
задает `WORKER_CONCURRENCY`.
