# Zvuk: локальный запуск на Windows 10/11 с VPN

Проверка локально **рекомендуется перед арендой хостинга**. Требуются Docker Desktop
с Linux containers (WSL 2), Git, свободное место на диске и память для нескольких сервисов.

## 1. VPN и Docker Desktop

1. Включите VPN на компьютере в режиме полного туннеля / системного VPN,
   а не только расширение браузера. При необходимости запустите Docker Desktop уже после VPN.
2. Сравните IP на Windows и в отдельном тестовом контейнере:

```powershell
Invoke-RestMethod https://api.ipify.org
docker run --rm curlimages/curl:8.15.0 -fsS --max-time 15 https://api.ipify.org
```

Если IP разные, нельзя считать, что Docker идет через этот VPN. Проверьте
split tunneling, сетевые правила VPN, DNS и маршрутизацию WSL 2.
В случае проблем приложение можно направить через настроенный сетевой прокси
или использовать другой VPN с полным туннелем. `PROXIES` в Zvuk
передается только yt-dlp и **не** перенаправляет автоматически весь трафик
Telegram Bot API, Spotify, AudD и PostgreSQL.

**Не публикуйте токен бота, API Hash и .env.** VPN не отменяет правил
медиаплощадок и не гарантирует доступность их источников.

## 2. Клонируйте проект и заполните .env

```powershell
git clone https://github.com/DizzyZ7/Zvuk.git
cd Zvuk
Copy-Item .env.example .env
notepad .env
```

Минимально заполнить `BOT_TOKEN`, `TELEGRAM_API_ID`,
`TELEGRAM_API_HASH`, `ADMIN_IDS`, `POSTGRES_PASSWORD`, `DATABASE_URL`
(пароль в URL такой же, как у PostgreSQL). `TELEGRAM_API_ID` и
`TELEGRAM_API_HASH` получают на my.telegram.org для Local Bot API,
токен — через BotFather.

На первом тесте рекомендуемые настройки:

```dotenv
PREMIUM_ENABLED=false
WORKER_CONCURRENCY=1
MAX_PENDING_PER_USER=5
MAX_FILE_MB=150
MAX_DURATION_SEC=600
AUDD_API_TOKEN=
```

Эти настройки ограничивают время и расход места на тестовые файлы;
распознавание не заработает, пока не задан действующий ключ AudD.

## 3. Перенос токена с публичного Telegram API

Если **этот токен уже использовался** с публичным `api.telegram.org`,
перед стартом собственного Local Bot API необходимо вызвать метод
`logOut` публичного Bot API. Введите токен через запрос, не добавляя его
буквально в сохраняемый скрипт:

```powershell
$token = Read-Host 'BOT_TOKEN (не публикуйте)'
Invoke-RestMethod -Method Post -Uri "https://api.telegram.org/bot$token/logOut"
Remove-Variable token
```

После успешного вызова можно сразу работать через Local Bot API,
но Telegram запрещает повторный вход на облачный API на 10 минут.
**Не выполняйте logOut многократно и не запускайте разные poller-ы
с одним токеном одновременно**.

## 4. Первый старт

```powershell
docker compose config -q
docker compose up --build -d
docker compose ps
docker compose logs --tail=100 bot worker telegram-bot-api migrate
docker compose run --rm --no-deps bot python -m app.tools.preflight
```

Preflight проверяет локальные TCP-порты, доступность некоторых HTTPS
доменов, наличие FFmpeg/Node и определяет внешний IP контейнера. Он не
печатает секреты. Для вызова уже должна быть поднята сеть Docker Compose.
Проверяйте ошибки по логам, а не только по статусу `running`.

Если невозможно подключиться к Telegram, сначала сравните IP контейнера и
хоста при VPN, DNS и логи Local Bot API. Установка `PROXIES` для yt-dlp
сама по себе не исправляет соединение локального Bot API с Telegram.

## 5. Живой функциональный smoke test

1. Отправьте `/start`, `/menu` и `/health` с ID в `ADMIN_IDS`.
2. Найдите публичный тестовый ролик, на который у вас есть права, и запросите MP3,
   затем тот же URL повторно: должен появиться отказ «уже отправлялся» без новой загрузки.
3. Проверьте MP4, 1.25× и 0.80× с коротким аудио.
4. Создайте `/playlist new Тест`, добавьте ссылку через `/playlist add ID URL | Тест`
   и откройте `/playlists`.
5. Проверьте `/fragment фраза песни`: результаты приблизительные, не
   гарантируется точное совпадение текста.
6. Проверьте `/library` и кнопку добавления в избранное.
7. `/economics` с администраторского аккаунта показывает только введенные вручную
   доходы/расходы в рублях; Stars учитываются отдельно.
8. AudD и платежи Stars оставьте выключенными, пока не завершен базовый тест.
   Включайте их поэтапно с реальными ключами и контролем затрат.

**Ни автоматические CI-тесты, ни preflight не подтверждают успешную
отправку файла пользователю.** Для этого нужен именно живой тест с ботом.

## 6. Остановка

```powershell
docker compose down
```

Не запускайте `docker compose down -v` без резервной копии —
он удалит тома PostgreSQL, Redis и Bot API.


## Проверка индивидуального выбора и дедупликации

1. Найдите `lil peep`, попробуйте 1, 2 и 3 треки подряд без нового поиска.
   Каждый должен отдельно попасть в очередь.
2. Повторно нажмите на первый трек. Ожидается «уже скачивается»,
   а после успешной отправки — «уже отправлялся». Новых задач быть не должно.
3. Попробуйте сразу пять разных треков с
   `MAX_PENDING_PER_USER=5` и `WORKER_CONCURRENCY=1`.
   Шестой не примется, пока одна из задач не завершится.
4. Перейдите на вторую страницу результатов, вернитесь обратно и проверьте
   соответствие статусов базе данных. Нет кнопки массовой загрузки.
5. Создайте `/playlist new Любимые` и добавьте найденный трек кнопкой
   `➕ Плейлист`.
6. После неудачного скачивания того же ролика нажмите кнопку снова:
   статус `failed` не должен блокировать новую попытку.
7. Отдельно проверьте MP3 и MP4 одного видео: они рассматриваются
   как два разных формата, но каждый должен быть отправлен только один раз.
8. Перезапустите бот без удаления томов и убедитесь, что повторная загрузка
   уже отправленного файла отклоняется по истории PostgreSQL.

После обновления на уже запущенном Windows:

```powershell
cd C:\Users\DizZy\Zvuk
git pull --ff-only
docker compose up --build -d
docker compose ps
docker compose logs --tail=100 bot worker
```

`.env` и тома PostgreSQL не теряются при штатном `git pull` /
`docker compose up --build -d`. Не вызывайте `docker compose down -v`.


## Проверка Reels, Shorts и TikTok (MP4 + MP3)

1. Отправьте боту ссылку на **публичный** Instagram Reel, который
   разрешено сохранять. Без меню форматов ожидайте **видео, затем MP3**
   со звуком именно из ролика.
2. Повторите ту же ссылку с другими параметрами (`?lqvp=...`):
   повторная отправка должна быть отклонена, без повторного скачивания.
3. Попробуйте YouTube Shorts и отдельную TikTok-ссылку.
   У каждого — тот же автоматический сценарий (два файла).
4. Для короткого видео без аудиодорожки отправляется MP4 и
   пояснение об отсутствии звука.
5. Если видео доставлено, но MP3 не удалось преобразовать, повторный
   запрос должен попытаться доставить недостающий звук **без повторного MP4**.
6. При стандартной ссылке YouTube `watch?v=...` меню форматов должно
   продолжать работать как прежде.
7. При ошибке Instagram/TikTok посмотрите `docker compose logs
   --tail=120 worker`. Некоторые открытые записи могут требовать
   авторизации на стороне площадки; VPN сам по себе это не решает.

Важное отличие: это *извлечение аудиодорожки*, а не автоматический поиск
полной композиции по названию. Для распознавания названия песни нужен AudD.


## PostgreSQL-only: миграция с Redis

Новая версия Zvuk использует одну PostgreSQL для истории, временных
поисковых кнопок, ограничений, кэша Telegram file_id и надежной очереди.
Redis и Upstash больше не нужны. Поддерживается PostgreSQL 17.

- Событие нового задания передается через PostgreSQL `pg_notify` внутри
  транзакции, которая записывает задачу в БД.
- Воркер использует `LISTEN zvuk_jobs`, `FOR UPDATE SKIP LOCKED` и
  временные SQL-аренды. При подключении и далее раз в 10 минут он
  восстанавливает незавершенные/просроченные задания.
- Администраторские FSM-диалоги, лимиты и временные результаты поиска
  хранятся в SQL-таблице `app_state`.
- Успешные отправки запоминаются в маленькой таблице
  `delivery_receipts`. Подробные завершенные логи удаляются спустя
  30 дней, поэтому защита от повторных отправок сохраняется.
- Старая история успешных скачиваний автоматически переносится в
  `delivery_receipts` миграцией `0007`.
- Непросроченные Redis-ключи (кнопки старого поиска, блокировки, троттлинг)
  не переносятся: после обновления пользователям достаточно повторить поиск.

Для обновления существующего компьютера:

```powershell
cd C:\Users\DizZy\Zvuk
git pull --ff-only
docker compose up --build -d --remove-orphans
docker compose ps
docker compose logs --tail=100 migrate bot worker
```

**Не выполняйте** `docker compose down -v`: это удалит PostgreSQL и
Telegram Bot API тома. Том старого Redis останется в Docker до ручного
очищения, что безопасно для данных. В существующем `.env` значение
`REDIS_URL` больше не используется и может быть удалено.

При внешнем PostgreSQL на Bothost важно обеспечить **прямое соединение**,
допускающее `LISTEN/NOTIFY`: соединение через PgBouncer в режиме transaction
pooling не поддерживает постоянную подписку на уведомления.
