# Zvuk — запуск и эксплуатация

## Подготовка
- Бот создан в BotFather. Не публикуйте токен.
- API_ID и API_HASH оформлены на my.telegram.org для Local Bot API.
- Для перехода с публичного Bot API, если этот токен уже был в использовании, сначала выполните `logOut` в соответствии с официальной инструкцией Telegram. Не запускайте одновременно два long-polling экземпляра.
- Сверьте `POSTGRES_PASSWORD` и пароль в `DATABASE_URL`.
- Переменные `ADMIN_IDS` и (при необходимости) `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET` заполнены.
- Для каналов ОП добавьте бота администратором и проверьте `getChatMember`.
- Опциональный cookies.txt храните вне git, только для использования администратором.
- Медиа скачивайте только при наличии необходимых прав.

## Развертывание
```sh
cp .env.example .env
# отредактировать .env
docker compose config -q
docker compose up --build -d
docker compose ps
docker compose logs --tail=100 bot worker migrate telegram-bot-api
```

`migrate` запускает `alembic upgrade head` до старта `bot` и `worker`.
Входящие запросы Telegram обрабатываются через long polling.
Файлы для Local Bot API временно хранятся в `/shared`.

## Проверка E2E

1. `/start` отвечает в личных сообщениях.
2. YouTube: видео -> выбор MP3 -> скачивание и `file_id` в Redis/БД.
3. Отправьте ту же ссылку: должен использоваться уже сохраненный `file_id`.
4. Выберите ⚡1.25×, затем 🌙0.80× по той же ссылке: проверьте скорость, длительность и разные ключи кэша.
4. Тот же URL -> MP4: отдельная запись кэша и загрузка видео.
5. Повторите проверки на публичных VK, Rutube и TikTok роликах.
6. Отдельно проверьте ссылку на общедоступный трек Яндекс.Музыки.
7. Для Spotify укажите client credentials и проверьте разрешение метаданных и альтернативный результат YouTube. Результат поиска не гарантирует оригинальную запись.
8. `/admin`: задайте рекламу; убедитесь, что caption обновляется без перезапуска и на попаданиях в кэш.
9. Настройте ОП: неподписанный пользователь получает список каналов, подписанный — файл.
10. Запустите тестовую рассылку на малой базе; убедитесь, что требуется подтверждение и кнопка остановки работает.
11. Попробуйте четыре разные ссылки, пока три задачи еще работают: четвертая должна получить сообщение о заполненной очереди.
12. Проверьте ограничение 1990 МБ, максимальную длительность и сообщения об ошибках на недоступном контенте.

## Наблюдаемость

```sh
docker compose logs -f --tail=100 bot worker
docker compose exec redis redis-cli XINFO GROUPS zvuk:downloads
docker compose exec redis redis-cli XINFO GROUPS zvuk:broadcasts
docker compose exec redis redis-cli XPENDING zvuk:downloads workers
docker compose exec redis redis-cli XLEN zvuk:downloads
docker compose exec postgres pg_isready -U zvuk -d zvuk
```

Контролируйте backlog, возраст pending-событий, дисковое место Docker volume, латентность загрузок, рост `download_history` и количество транскодирований. Redis append-only включен. Сохраняйте резервные копии PostgreSQL.

## Сценарии сбоев

- **Telegram ограничивает запросы**: повторно используйте `file_id`, уменьшите параллелизм и дождитесь RetryAfter.
- **Redis/БД кратковременно недоступны**: задача остается в pending stream для последующего восстановления, но после лимита попыток может завершиться ошибкой.
- **Worker аварийно завершился**: новые экземпляры возвращают незавершенные задачи через XAUTOCLAIM спустя примерно 3 минуты. Возможна повторная отправка файла в узком окне между API отправкой и фиксацией статуса.
- **Бот не видит подписчиков канала**: убедитесь, что у него права администратора и правильный chat_id.
- **Файлы занимают диск**: TemporaryDirectory удаляется в нормальном режиме и при обрабатываемых ошибках; после SIGKILL/аварии могут остаться директории `/shared/zvuk_*`. Удаляйте их только после остановки воркера, убедившись, что загрузка не выполняется.
- **Долго идет рассылка**: остановите через inline-кнопку; уже отправленные копии остаются. Новых подписчиков, зарегистрировавшихся после запуска рассылки, воркер не добавляет.
